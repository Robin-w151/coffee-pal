## Technical notes

- Don't update the visual snapshots in this story; the v2 baseline stays as the reference until the human approves v4 at checkpoint 18, after which Claude commits the v4 baseline.

### As built (2026-10-28)

- **Input groups:** `MeasurementInput`, `UrlInput` and Estimation use `ig-input`, `ig-select` and `ig-cell`. `input-group-divider` is gone (v4 always draws dividers). The minimum widths select the new classes (`[&_.ig-input]:min-w-40`, `[&_.ig-select]:min-w-24`) and no longer need `!important`, because no v2 rule competes. This fixed the white, unreadable unit fields in dark mode. The select-width e2e test still passes.
- **`input-error`:** v4 has no state classes for inputs, and six call sites use v2's `input-error`. `app.css` now defines it as an `@utility` (error ring plus a light error tint) that works on `.input` and `.input-group`, so the call sites stay unchanged.
- **Leftover v2 classes outside the status rule:**
  - `divider-vertical` → `vr` plus `border-t-0` on the `<hr>`.
  - Plain `<hr>`s fell back to the v3 compatibility border colour (`gray-200`, near-white in both modes), as v4 no longer styles bare `<hr>`s. `app.css` gives `hr` the `surface-200-800` colour of Skeleton's `hr`/`vr` in the base layer (human's finding, 2026-10-28).
  - `list-dl` was dropped. The list items set their own layout, but the list placeholders relied on its flex rows (badge and circle collapsed, human's finding, 2026-10-28); they now carry `flex items-center gap-4 p-2` themselves.
  - `list-nav` (AppMenu) → explicit link layout, with hover only on inactive links.
  - `migration-status` now counts `list-nav`, `list-dl` and `divider-vertical` as v2 classes, and no longer counts `input-group` itself, which is valid in v4.
- **Cards:** v4's `card` has no background (v2's had the surface colour), so sections floated on the mesh, and the input outlines disappeared in light mode. PageCard, the active search header, the Nextcloud login modal and the confirm dialog use v2's card colours, `bg-surface-100 dark:bg-surface-800` (first `bg-surface-50-950`; changed after the human's review, see below).
- **A11y:** v4's segmented controls and file upload fixed Settings' `label` and `nested-interactive` violations. The baseline was shrunk in its own commit (Settings now has none).
- **Review page:** `scripts/visual-review.js` plus `pnpm visual:review` and `pnpm visual:review:base` (`--base <ref>` compares committed baselines and embeds the images from git as data URIs). The output stays in `test-results/` (ignored).
- **Field outlines (human's decision, 2026-10-28):** fields have 3px outlines in the `surface-400-600` pairing (v4's default `surface-200-800` was barely visible against the cards and the field background). `app.css` redefines only `--default-ring-width` and `--color-surface-200-800` on the field elements (`.input`, `.select`, `.textarea`, `.input-group`, and the combobox, tags input, dropzone and segmented control parts), plus a 2px border width for the two that are border-based. Focus rings, dividers and other surfaces are unchanged.
- **Field backgrounds (human's finding, 2026-10-28):** v4's fields are transparent, so they had the card colour. Like v2 (fields one surface step off the cards), they now use v2's surface 200 in light and 700 in dark mode (human's choice; `--coffee-field-background`, as it isn't one of the theme's pairings) against the cards (surface 100 / 800): set on the field groups and Zag parts in the components layer, and merged into the `input`, `select` and `textarea` utilities via `@utility`, because Skeleton's own `transparent` there beats the components layer. `input-error`'s tint is now mixed into that background and `!important`, so it still wins over the merged `input` rule.
- **Field padding (human's finding, 2026-10-28):** fields are back to v2's 0.5rem vertical padding (v4: 0.25rem), merged into `input`, `select`, `textarea`, `ig-input` and `ig-select` and set on the combobox input. All of them are now 43px tall, in line with the tags input (42px).
- **Input group focus (human's finding, 2026-10-28):** v4's `input-group` has no focus state, so a focused `ig-input`/`ig-select` only got the forms plugin's 1px ring on itself, and the unit select next to it wasn't outlined. `app.css` merges `:focus-within` (primary ring colour) into `input-group` and removes the children's own ring on focus, so the whole group gets the 3px focus outline like single fields. The cells' divider borders painted over the group's inset ring and split it, so the ring is now also drawn on an `input-group::after` overlay above the cells (`--tw-ring-color: inherit` there, as Tailwind registers it as non-inheriting).
- **Dark shell shades and header shadow (human's finding, 2026-10-28):** as in v2, the header and cards are a step lighter than the sidebar in dark mode: header and cards `surface-800`, sidebar 900, fields 700. In light mode the cards are v2's `surface-100` again (`bg-surface-100 dark:bg-surface-800`), with fields 200; header 100. The header has v2's `shadow-xl` again.
- **Error fields (human's finding, 2026-10-28):** `input-error` uses v2's colours again in both modes: `error-200` background, `error-500` outline, text and placeholder (the earlier 15% tint was barely visible, and text stayed normal). In input groups the cells inherit the text colour and the dividers turn `error-500` too. Text contrast is about 4.8:1. The combobox (brew method) only passed `invalid` to Zag, so its input now also gets `input-error`. Placeholders differed between fields (Skeleton's `surface-700-300` on `.input`, `.textarea` and `.ig-input`, the forms plugin's grey on the combobox and tags input). All now use v2's colour, the forms plugin's `gray-500` in both modes (human's choice).
- **Tables (human's finding, 2026-10-28):** as in v2, headers are bold and share the alternating rows' background, and cells have `1rem 0.75rem` padding (v4: normal weight, no header background, `0.5rem`). Header and stripes use surface 200 / 700 (v2's header colours); the old `surface-200-800` stripes were invisible on the dark `surface-800` cards. This lives in `app.css` (merged into `table`) instead of a stripe class on each table. Headers use the cells' horizontal padding (v2 had 1rem) so columns line up. Header text is white in dark mode (Skeleton's `surface-700-300` otherwise; human's choice).
- **Loading placeholders (human's finding, 2026-10-28):** v4's `placeholder` / `placeholder-circle` use `surface-200-800`, the colour of the light table stripes and the dark cards, so the table skeleton bars vanished on every other row. They now use surface 300 / 500 (v2: 300 / 600, but 600 barely shows on the 700 dark stripes). Applies to the table rows, the mobile list items and the page header skeleton.
- **Button sizes (human's finding, 2026-10-28):** v2's sizes again: `btn` padding `9px 1.25rem` (about 42px tall; v4: 32px), and icon buttons as fixed squares of 42px (`btn-icon`, see below), 28px (`btn-icon-sm`, see below) and 53px (`btn-icon-lg`) (v4: 32, 24, 44px).
- **Text and heading sizes (human's finding, 2026-10-28):** the theme conversion (story 14) had set `--text-scaling: 1.067`, which v2's theme never had, so all text was 6.7% larger (body 17px). It is 1 again. v4's headings are also one size step larger than v2's (h2 on phones 1.875rem vs 1.5rem), so `app.css` sets h1–h6 to v2's sizes. On a 375px phone the page title (h2) is 24px again, and the header's sort button no longer runs off the screen. With the smaller line height, buttons are about 42px and fields about 40px tall, close to v2.
- **Popup transitions (human's finding, 2026-10-28):** v2's popups faded in and out (150ms opacity); v4's `Popover` and `Combobox` content have no animation and are hidden at once on close. Both wrappers render their content through the `element` snippet inside `{#if open}` with `transition:fade` (150ms), keeping `hidden` off during the fade-out.
- **Switch track (human's finding, 2026-10-29):** off switches used v4's `surface-200-800` track, barely visible on the cards (invisible in dark mode). They now use surface 400 / 500 (v2: 400 / 700; 700 barely shows on the dark 800 cards).
- **Tonal presets (human's finding, 2026-10-29):** the codemod mapped v2's `variant-soft-*`/`variant-ghost-*` to `preset-tonal-*`, whose light background (shade 50) is barely off the cards, e.g. the calculator's preset chips. In light mode `preset-tonal-{primary,secondary,tertiary,error}` now use v2's soft colours (20% tint of shade 400, shade-700 text); dark mode keeps v4's.
- **Button press animation (human's finding, 2026-10-29):** v2's buttons shrank to 95% while pressed (noticeable on the drip counter's Tap and Reset); v4's don't. `btn` and `btn-icon` scale to 95% on `:active` (not when disabled), using the existing 150ms transition.
- **`dpm` cell (human's finding, 2026-10-29):** v4's `ig-cell` centres its content in a smaller font, so the drip counter's `dpm` unit sat centred unlike the unit selects. That cell is now `justify-start px-3 text-base`, in line with the select text above it. Other `ig-cell`s (the URL input's icons) stay centred.
- **Drawer animation (human's finding, 2026-10-29):** v2's drawer slid in from the left with a fading backdrop (200ms, off for reduced motion); v4's `Dialog` has no animation. DrawerHost renders backdrop and content through `element` snippets with `fade` and `fly|global` (the content's `{#if}` sits outside `Dialog.Content`), keeping `hidden` off while they animate out, and keeps the last drawer id so the content stays rendered during the slide-out. Duration 0 when `prefersReducedMotion`.
- **Pagination on phones (human's finding, 2026-10-29):** v4's pagination shows page numbers (v2's showed only arrows), and its triggers build on `btn`, so with v2's button padding it ran off the card on phones. Below `sm` it now shows one page around the current one (`siblingCount` 0, via `MediaQuery` on `screens.sm`) with tighter spacing (`gap-1 p-1`, triggers `px-2`); below 360px the first/last triggers are hidden too. Widest state: 278px of 296px at 360px, 210px of 256px at 320px. Desktop is unchanged apart from `px-3` triggers.
- **Trail button (human's finding, 2026-10-29):** `btn-icon-sm`, only used for the buttons inside fields (`InputWithButton`: coffee link, search clear), is 28px instead of v2's 33px, which nearly filled the 40px fields; it sits `right-1.5`, so 6px on top, bottom and right.
- **iOS: app scrolls up with the keyboard (human's finding, 2026-10-29):** v4's hidden inputs (e.g. the file upload's) are `position: absolute` with no positioned ancestor, so they sat outside `#page`'s clipping and made `<html>` 65px taller than the viewport on Settings. `overflow: hidden` doesn't stop `scrollIntoView`, so iOS scrolled `<html>` to show a focused field (keyboard, developer switch), moving the header off screen and leaving a gap at the bottom. `#page` is now `relative`, so such content is placed and clipped inside it; `<html>` stays at the viewport height and scroll 0 on all pages (checked at 375×667, focusing fields and turning on the developer section). The keyboard itself was not reproducible in the browser.
- **URL scheme select (human's finding, 2026-10-29):** `UrlInput`'s select had `px-3`, which overrode the 40px right padding `ig-select` keeps for its arrow, so the arrow covered `https://`. Without it the select is 104px wide and the text ends before the arrow.
- **Field height = button height (human's finding, 2026-10-29):** fields use 9px vertical padding (was 0.5rem), so inputs, input groups, combobox and tags input are 42px tall like text buttons; icon buttons are 42px squares (v2: 43px), so e.g. the search field and the sort button line up.
- **Table row hover (human's finding, 2026-10-29):** both tables kept v2's `table-interactive`, which v4 doesn't define, so rows had no hover state. `app.css` defines it again: pointer cursor and a 10% primary tint on hover, on the cells (`td` background over the row's stripe), so striped rows are tinted rather than lightened and the tint fades in and out over 150ms like the list items' hover (human's request, 2026-10-29).
- **Segmented control height (human's finding, 2026-10-29):** its items build on `btn`, so they took the buttons' v2 padding inside v4's 8px control padding (64px tall). Control and items now use v2's RadioGroup spacing (`p-1 gap-1`, items `py-1 px-4`): 46px tall, as in v2.
- **Navigation rail (human's finding, 2026-10-29):** v4's rail is 100px with 8px padding and gaps, and its tiles are buttons that got the buttons' v2 padding. It now has v2's geometry: 80px wide, 4px padding and gaps, 72px tiles with 4px padding. The app bar's left padding on md+ is 4px (`md:pl-1`), so the title's coffee icon is centred over the rail icons at 40px, as in v2.
- **Slider label (human's finding, 2026-10-29):** v4's slider label is extra small and medium weight; it now uses `text-base font-normal` like the other field labels (16px, normal).
- **Slider colours (human's finding, 2026-10-29):** range, thumb ring and focus outline use `primary-500` (v4: `surface-950-50`); the track uses the off switches' surface 400 / 500 (v4's `surface-200-800` vanished on the dark cards), and the thumb is light in both modes like the switch knob.
- **Toast layout (human's finding, 2026-10-29):** below `sm` toasts were `flex-col` (from phase 1), stacking message, action and close button centred on phones. They are a row on all widths again, as in v2: the message takes the room left (`flex-1 min-w-0`) and wraps; action and close sit on the right.
- **Popover:** the unused props (`openOn`, `placement`, `matchWidth`, `portal`, `trapFocus`, `contentClass`, `onOpenChange`) are removed; PageSearch only passes `trigger` and `content`.
- **Combobox focus bug (found while verifying the above):** with the `open` state controlled (story 16), Zag's `CONTROLLED.CLOSE` lost the `restoreFocus: false` of an outside interaction and refocused the input a frame later, even after the user had moved on. Text typed into the next field then landed in the brew method or coffee type ("Tovolea Classic98"), and "entry add" failed about 1 in 5. `open` is now uncontrolled (`useCombobox` + `Combobox.Provider`), and Escape closes through the API, because Zag's own Escape handling is a layer it sets up only after opening. Suggestions open on click and typing, no longer on focus alone. _Test change:_ `JournalEntryDetailPage.closeSuggestions` and `fillCombobox` wait one frame for Zag's own refocus of the input (after opening or Escape) before the test types into the next field, which no human could do that fast. After this, the journal and app shell specs passed 5× in a row (270 runs).
- **Icon buttons (human's finding, 2026-10-28):** v4's `btn` and `btn-icon` are separate utilities, so using both mixed `btn`'s padding, line-height and gap into icon buttons. Icon-only buttons now use `btn-icon` alone (AppBar, AppMenu, PageHeader, PageActions, PageSearch, InputWithButton). `ResponsiveButton`, which hides its label below `lg`, uses `lg:btn max-lg:btn-icon`. `app.css` gives `btn-icon` the same hover transition as `btn` (a second `@utility btn-icon` that Tailwind merges into Skeleton's).
